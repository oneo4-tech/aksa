# Memory and knowledge base

Read before retrieving from, adding to, reviewing, or repairing Memory (`agentic/memory/`) or the Knowledge Base (`.kb`). Terms are defined in `agentic/memory/vocabulary.md`.

## Tiers

| Tier | Holds | Retrieve | Write |
|---|---|---|---|
| Memory | Facts about aksa: `vocabulary.md`, `decisions.md`, `decisions-history.md` | `get-memory` | `add-memory`, `repair-memory`, with the owner's agreement |
| Knowledge Base | Domain knowledge, independent of aksa | `get-kb` | `add-kb` to the inbox; `review-kb` into the wiki; `repair-kb` |

- Facts about aksa never go to the Knowledge Base; domain knowledge never goes to Memory (D-015).
- Vendor auto-memory holds personal preferences only (D-019).
- Change Memory or the Knowledge Base only through these skills.

## Retrieval

- Read the least that answers the question: grep or index first, summaries next, whole files last. The steps are in `get-memory` and `get-kb`.
- Cite the file path of each fact used. Never treat `inbox/`, `raw/`, or `outputs/` content as trusted knowledge.

## Knowledge Base layout (D-017)

| Path | Purpose | Retrieved |
|---|---|---|
| `index.md` | One line per wiki page, generated by `agentic/scripts/kb_index.py`; never edit by hand | Always first |
| `wiki/<domain>/<topic>.md` | Curated, owner-approved pages; the only trusted content | Yes |
| `inbox/<YYYY-MM-DD>-<slug>.md` | Captures awaiting `review-kb` | No |
| `raw/<YYYY-MM-DD>-<slug>.<ext>` | Immutable source documents cited by pages or inbox items | Only to verify a citation |
| `outputs/` | Generated deliverables of domain knowledge, such as research; never notes about aksa work, such as handoffs (D-015) | No |
| `log.md` | Append-only: `- YYYY-MM-DD <action> <path>: <note>`, actions `add`, `approve`, `drop`, `repair` | No |

- Domain, topic, slug, and tag names are lowercase hyphenated. Reuse an existing domain or tag from `index.md` before creating one.
- The Knowledge Base is its own git repository (D-018). Each skill run that changes it ends with `git -C .kb add -A && git -C .kb commit -m "<action>: <summary>"`.

## Wiki page contract

```markdown
---
summary: One sentence; becomes the index line.
tags: [tag-one, tag-two]
updated: YYYY-MM-DD
sources: [raw/2026-10-19-example.pdf, https://example.com]   # optional
---
**TL;DR** Two to four lines that answer the common question.

## Details
```

- One topic per page, at most 6000 characters (about 1.5k tokens); split larger pages. **[checked by `kb_index.py`]**
- Frontmatter fields as above. **[checked by `kb_index.py`]**
- The TL;DR comes first so a 12-line read is enough to judge relevance.
- Link related pages with `[[topic]]`; state facts once and link instead of copying.

## Inbox item contract

```markdown
---
summary: One sentence.
sources: [raw/2026-10-19-example.pdf]   # optional
captured: YYYY-MM-DD
related: [wiki/domain/topic.md]         # optional: pages it may update
---
<The knowledge, in the capturer's words.>
```
