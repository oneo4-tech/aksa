# Build video demo

## Inputs and prerequisites

- The owner's feedback rules: `agentic/skills/content/run-youtube/references/feedback-rules.md`, its rows for step `build-video-demo`.
- The channel and `#<n>`, a content issue at stage `demo` (from `youtube-producer`), with gate 2 not in `approved`. No channel or issue: ask the owner which.
- Written below: `C` for `uv run agentic/scripts/content_issue.py`, `S` for `uv run agentic/skills/content/build-video-demo/scripts/scaffold.py`, `V` for `uv run agentic/skills/content/build-video-demo/scripts/record.py`, and `W` for the workspace `.projects/content/yt-<channel>/`.
- The channel workspace, checked with `uv run agentic/scripts/youtube_channel.py check <channel>`; exit 2: show its message and stop. Read the style guide sections `Screen capture` (terminal demo rules) and `Gate 2 checklist` (what the owner checks of the demo plan), and in `channel.yaml` the `demos` repository and clone folder that `S` uses.
- The script and research: `W/videos/<n>/script.json` from `write-video-script` (its `code` and `split` scenes name the demo files and their marked lines, its `terminal` scenes the commands shown, its `kit` scene's `files` the AI kit's files, each with how the viewer uses it), the "The demo must prove" list of `W/videos/<n>/research.md`, and `W/videos/<n>/citations.json`, every claim verified by `research-video`, which the README lists. Missing: stop and route the video back to `write-video-script` or `research-video`.
- `uv` to run the demo's tests, and `vhs` to record the tape, plus `whisper-cli` with its `base.en` model (as `render-video` uses) once the video has narration; without them, ask the owner to install them and report the recording blocked.

## Procedure

1. **Check the stage:** `C status <n> --channel <channel>` must show stage `demo` with gate 2 not in `approved`; else stop and report the stage.
2. **State the claim** in one sentence: what the demo proves, from "The demo must prove" and the script's climax scene. Pick a slug of two or three lowercase hyphenated words naming it.
   - **State the kit:** the rules an agent follows so it does not skip the questions the video highlights, from the video's tester questions and its principle beat; each one sentence, phrased as a rule ("Before you call a test done, name the change that would make it fail."). Name its skill verb-object, such as `check-test-can-fail`.
3. **Scaffold:** `S <channel> <n> --slug <slug> --proves "<the sentence>" --skill <skill> --rule "<rule>"`, one `--rule` per rule. It creates `<n>-<slug>/` in the clone with `README.md`, `demo/`, `tests/`, `demo.tape` (from `references/demo.tape`, with the README from `references/readme-template.md`), and `ai-kit/` (`AGENTS.md` from `references/kit-agents.md`, `skills/<skill>/SKILL.md` from `references/kit-skill.md`, and an empty `scripts/`), and prints the description link. The README's Video section holds the line `- Video: not published yet`, which `package-video` fills with the published video's link, the channel's link, and the folder's link; its Sources section lists each claim with its quoted line and text-fragment link. It never links the content issue: the aksa tracker is private.
   - Exit 3, folder exists: a rebuild; continue that folder. Exit 3, clone missing or repository missing on GitHub: ask the owner (see Constraints), then run `S` again; no yes: report blocked. Exit 3, citations not verified: route the video back to `research-video`.
   - Exit 2: fix the input it names.
4. **Build the smallest demo** that proves the claim, test first: the files each `code` or `split` scene names go in `demo/` and `tests/`, at those paths, each marked line at its `line`, and nothing the video does not show. A claim that a kind of test misses a defect shows the weak test and a step that breaks the code, then restores it, as the prototype's `mutate.sh` did; these stay in `demo/`.
   - **Code a viewer would ship,** never a toy function: a slice of a realistic service, such as a checkout, coupon, pricing, or payment service; realistic values, such as prices in integer cents with a currency; and at least one real collaborator worth mocking, such as a tax or payment client, so mocking the right thing and the wrong thing both look plausible.
   - **A step that changes the code** (a mutation) prints the changed line before and after, such as `- (1 - percent / 100)` and `+ (1 + percent / 100)`, so the viewer sees the mutated code; running the tests on it is a separate step (step 7). `tests/` holds the tests that prove the claim, passing on the correct code, each with one reason to fail. Standard library and pytest only, unless the claim is about another tool.
5. **Build the AI kit** in `ai-kit/`, which a viewer copies into their own project:
   - `AGENTS.md`: the rules as `S` wrote them; sharpen wording only.
   - Every file the script's `kit` scene lists exists at its `path` in `ai-kit/` and does what its `use` line tells the viewer (`check_script.py` checks each path once `demo.json` exists); a file the kit needs that the scene does not list goes back to `write-video-script`.
   - `skills/<skill>/SKILL.md`: an Agent Skill (frontmatter `name` and `description`) usable from `.claude/skills/` or `.agents/skills/`; make its procedure ask and answer each rule before the agent accepts its work, naming the commands that give the evidence.
   - `scripts/<name>`: a runnable helper when one turns a rule into a check, such as one that flags a test patching the function it calls; standard library or the demo's tools only, run as `python3 ai-kit/scripts/<name>` from the project root, and called from the skill's procedure. Code gets a test in the folder's `tests/`, such as `test_ai_kit.py`, running it on the demo's weak and good examples. No helper: the skill's rules stand alone and `scripts/` keeps its `.gitkeep`.
6. **Run the tests** from the folder: `uv run --with pytest python -m pytest -q tests`; fix the demo until it exits 0. Run each `demo/` step the tape types and check its output is what the script's `terminal` scenes say.
7. **Write the tape:** in `demo.tape`, keep the settings and the hidden setup line, and replace the `Show` part with the `terminal` scenes' steps in order, as `Screen capture` sets. Start each `terminal` scene's steps with a comment line `# scene` (a label may follow a colon, such as `# scene: boundary mutant`), one per `terminal` scene in script order; the part before the first marker is the shared setup. Each section is recorded alone after that setup, so it must not depend on an earlier section's state; its clip must not outlast its scene (render-video refuses a longer clip and holds a shorter one's last frame).
   - **One step per narrated sentence:** each sentence of a `terminal` scene's `say` that explains a step gets one `# comment` step, in order, whose comment starts with a key word the sentence says (its leading key word, as `render-video` cues an item), such as `# break the code` for "Now we break the code."; then its command. Each output the narration explains is its own step, such as the mutation printing its change, then a separate `# comment` step running the tests, never one script running both, so no output appears before the narrator reaches it. A sentence without its step, or a step whose comment the narration never says: route the script back to `write-video-script`.
   - Keep the template's hidden setup: each step is a `# comment` line, its command, and its output, read as a group, ending on a `Sleep` that `V` sets from the narration; the setup's `zshaddhistory` hook records whether the last line was a comment (zsh's `preexec` skips comment-only lines) and its `precmd` prints one blank line before the next prompt unless it was, so one blank line comes before each `# comment` step and none between a comment and its command. Give every step its comment line, such as `# both test files pass` then `pytest -q tests`, and `# break the code` then the mutation step.
   - **Record it:** `V <channel> <n>` records each section with `vhs` from the folder and moves it to `W/videos/<n>/demo-1.mp4` ... `demo-K.mp4`, one per `terminal` scene. Without narration it records the tape as written, so the steps can be checked at gate 2. Once `narrate-video` has written `narration/NN.wav`, `youtube-producer` runs `V` again at stage `recording`: it transcribes each `terminal` scene's narration and sets the section's `Sleep`s so each `# comment` step starts as its sentence starts, the last holding to the scene's length. Exit 3: the markers do not match the script's `terminal` scenes (fix the markers); a step's comment is never heard in its narration (start the comment with a key word its sentence says, else route the script to `write-video-script`); or a step, or the scene's end, comes before the tape can reach it (shorten the step before it, else route the script to `write-video-script` for more words before it). Exit 2: fix the input it names. Exit 1: `vhs` or `whisper-cli` missing or failing; report its message. Watch each clip and fix any step that shows an error the script does not expect.
8. **Fill the README:** adapt "How to run" if the demo needs more than the command above, and add each `demo/` step a viewer runs. In "Use it with your AI agent", add each kit script with what it checks and a command running it on the demo. No `{{` placeholder is left; keep the `- Video:` line and the Sources section as `S` wrote them, for `package-video` to fill at publish.
9. **Commit in the clone,** never in aksa: `git -C <clone> add <n>-<slug>` and `git -C <clone> commit -m "feat(<n>-<slug>): add the demo"`. Ask the owner for an explicit yes to push; on yes, `git -C <clone> push`; else leave it local and report the push waiting.
10. **Record the link:** write `W/videos/<n>/demo.json` with `folder` (`<n>-<slug>`), `link` (the description link from `S`), `proves` (the sentence), and `pushed` (`true` or `false`); `package-video` puts `link` in the description.
11. **Report on the issue:** write a scratch file of the line `YouTube: demo`, then the claim, the link, the kit's link (`<link>/ai-kit`) with its `AGENTS.md` rules and the skill's name as snippets to share, the test result line, and whether it is pushed, and post it with `gh issue comment <n> --body-file <file>`. Return to the producer, checking the demo against `Gate 2 checklist` and noting each item it fails.

## Output

The `YouTube: demo` comment's link, the description link, the kit's link and its rules as a snippet for the owner, the test result line, the recording paths, and whether the folder is pushed. A refused channel, a stage mismatch, a missing script, a missing clone or repository, missing `vhs`, or tests that cannot pass are reported as blocked with the command's message.

## Constraints

- Never create the public demo repository, or push to it, without the owner's explicit yes in this session. Creating it is a one-time owner-approved step: on that yes, `gh repo create <demos.repo> --public --license mit`, then `gh repo clone <demos.repo> .projects/content/<demos.path>`.
- The folder is public: no secrets, `.env` values, absolute paths, links to the private aksa tracker, channel workspace text beyond the README, or code copied from a source whose licence does not allow MIT redistribution.
- Generated media stays out of git: the folder's `.gitignore` ignores it, and the recording lives in the channel workspace.
- Never passes a gate, moves a stage, or edits labels or the body; `C` and `youtube-producer` own those (D-047). Never edits `script.json`, `citations.json`, `channel.yaml`, or the style guide; a script that the demo cannot back goes back to `write-video-script`. Never commits workspace or demo files to aksa.

## Done when

- `uv run --with pytest python -m pytest -q tests` exits 0 in the folder, and the tape's steps match the script's `terminal` scenes: one `# comment` step per narrated sentence, its comment starting with a key word the sentence says, and each explained output its own step.
- `demo/` is a slice of a realistic service with realistic values and a real collaborator, not a toy function; every step that changes the code prints the line before and after, and the recording shows one blank line before each `# comment` step and none between a comment and its command.
- The folder has `README.md` with no placeholder, the `- Video:` line, the channel link, the "Use it with your AI agent" section, the Sources section, and no aksa issue link, `demo/`, `tests/`, and `demo.tape` with the template's settings; `demo.tape` has one `# scene` marker per `terminal` scene, and the recordings are at `W/videos/<n>/demo-1.mp4` ... `demo-K.mp4`, one per `terminal` scene, or reported blocked.
- `ai-kit/` has every file the script's `kit` scene lists, at its path and doing what its `use` line says (`check_script.py` checks each path once `demo.json` exists), `AGENTS.md` with the video's rules, `skills/<skill>/SKILL.md` with `name` and `description` frontmatter, and each helper in `scripts/` called by the skill and tested in `tests/`, passing.
- `W/videos/<n>/demo.json` holds the description link, and nothing was pushed or created without the owner's yes.
- The `YouTube: demo` comment is on the issue, with no placeholder and no em dash.
