F Factory — Phased, Gated Lifecycle

A Run takes one Software Work Request from triage to close: one factory issue, at most one merged PR into main. Large runs get spec and plan stages; small runs skip them.

triage → G0 → concept → G1 → define → G2 → spec → G3 → plan → build → ship → merge
triage route / close
triage-request
Checks duplicates, earlier rejections, existing work. Routes to concept when discovery needed (open decisions, unknown feasibility, research, prototype), else to define. Owner can close as duplicate/won't-do.
concept G0: feasibility verdict
define-concept (helpers: research-topic, build-prototype)
Settles open decisions one at a time with owner. Prototypes answer one design question by clicking on a never-merged branch. Ends with G0 — decisions settled + verdict. Not feasible = close issue.
define G1: requirement approved
define-requirement
Writes the Requirement: problem, outcome, acceptance criteria (AC1…ACn) each with its test, out of scope, constraints. Proposes type (feature/enhancement/fix/chore), size, title.
spec (large runs only) G2: spec approved
define-spec
Designs approach, interfaces (each real choice designed twice), test for each AC, notes for planning. No code written yet.
plan (large runs only) G3: task checklist + int branch
plan-tasks
Splits into ordered vertical slices (tasks), each checkable, fitting one session. Pushes integration branch int/-. Every AC covered by at least one task.
build every task landed
implement-task → verify-task (per task, in order)
Tasks run one at a time on branches /-t-. Test-first, small conventional commits. Each task verified by independent reviewer before landing on integration branch. Helpers: diagnose-bug, resolve-merge-conflicts.
ship owner merge
ship-change
PR up to date with main, CI passing, verified work covers all ACs. Asks owner for review feedback. Merges into main only on owner's explicit yes. Closeout.

A Agents — Harness & Operators

Agents are first-class components with a goal, role, and owned outcome. They use rules and skills.

factory-orchestrator owns the run
agentic/agents/factory-orchestrator.md
The main session for a factory run. Owns outcome end-to-end. Talks to owner at gates. Spawns sub-agents (which cannot spawn others). Started by run-factory skill.
Sub-Agents explore · general
Via subagent tool
explore — fast codebase search, pattern finding, Q&A. general — multi-step research, parallel execution. Orchestrator delegates focused work; stays in control.
Agent Principles (Guidance)
AGENTS.md — Agent Principles section
Think Before Coding: state assumptions, present alternatives, push back on complexity, stop when unclear, guess cheap-to-undo when owner absent. Simplicity First: minimum code, no speculative features, handle real failures, rewrite 200→50 lines.

C Components — Governed Standards

Every piece of aksa is a Component — versioned, reviewable, held to a single standard in agentic/rules/components.md (D-014).

📜
Rules
Persistent behaviour & constraints. AGENTS.md = root rule (always loaded). Conditional rules in agentic/rules/.
⚙️
Skills
Conditional task procedures. Categories: factory (lifecycle), core (memory/kb), auxiliary (helpers). Synced to all vendors.
🤖
Agents
Operators with goals & roles. factory-orchestrator runs runs. Live in agentic/agents/.
🧠
Memory
Governed context about aksa: vocabulary.md (terms), decisions.md (active), decisions-history.md (superseded). Changed only via add-memory.
🔧
Scripts
Deterministic executable work. link_external, sync_vendors, new_worktree, factory_issue, kb_index, check_pr_review. Read config/.
📋
Templates
Starting structures for rules, skills, agents. Live in agentic/templates/.
Governance review-component
agentic/skills/core/review-component
Every new or changed component passes review-component before acceptance. One standard for authoring, review, and checks — avoids drift. CI (check_pr_review.py) blocks PRs changing components without a review result.
Vendor Neutrality sync_vendors.py
agentic/scripts/sync_vendors.py
Sources stay vendor-neutral in agentic/skills/. Synced to .claude/skills (Claude) and .agents/skills (Codex, Gemini, Copilot, OpenCode) with vendor frontmatter added. Repo-level only (D-003).

T Tools — Deterministic Scripts

Shared scripts in agentic/scripts/ read settings from config/. No business logic in skills — skills orchestrate, scripts execute. The only code touching external systems directly.

🔗
link_external.py
Creates/repairs .kb, .projects, .worktrees symlinks from config/environment.yaml (only file with absolute paths, D-012)
🔄
sync_vendors.py
Syncs skills to .claude/skills, .agents/skills with vendor frontmatter
🌳
new_worktree.py
Creates git worktree under .worktrees/ with links & vendor folders set up
📋
factory_issue.py
Only writer of factory issue labels & body; status reads run, labels syncs label set from config/factory.yaml
📚
kb_index.py
Rebuilds .kb/index.md from wiki frontmatter; --check validates
🔍
check_pr_review.py
CI gate: fails PR changing components without review-component result
Checks (Must Pass Before Commit) pre-commit & CI
uv run pytest, ruff check, ruff format --check
Pre-commit hook runs all three + vendor sync check. CI (.github/workflows/check.yml) runs same. PR review check (review.yml) requires review-component result section.

S State — Issue-Centric Truth

All run state lives in the Factory Issue — labels, body sections, task checklist, Factory: comments. Never in local files or vendor memory (D-024).

🏷️
Labels
Exactly one stage:*; type:* & size:* from G1; needs:owner; claimed
📄
Body Sections
Request (quoted, never edited), Concept, Requirement, Spec, Delivery — each written by its stage
✅
Task Checklist
Markdown list, ticked as tasks land. GitHub counts only tasks (no checkboxes in prose).
💬
Factory Comments
Stage moves, gate results, verify reports, blockers, needs, claims, owner review, ship summary
Claims one session at a time
factory_issue.py claim / release
Session claims before work: factory_issue.py claim --session . Releases on stop. Takeover only on owner's yes. Prevents races on integration branch & issue.
Owner in the Loop G0–G3 + merge
factory_issue.py set --owner wait/clear
Gates G0–G3 and merge need owner's explicit yes (recorded in Factory: comment). Owner also decides: triage close, concept interview, new terms/decisions, build blockers, true merge contradictions, findings still blocking after confirm pass. Factory lands verified tasks & updates own issues without asking.
Memory & Knowledge: Two Tiers, Never Confused D-015
get-memory / get-kb
Memory (Component): agentic/memory/ — facts about aksa: vocabulary.md, decisions.md, decisions-history.md. Changed only via add-memory with owner agreement.
Knowledge Base (External): Own git repo at .kb/ — inbox/, raw/, wiki/ (trusted), outputs/. Only wiki/ retrieved. Entries reach it only through review-kb.
